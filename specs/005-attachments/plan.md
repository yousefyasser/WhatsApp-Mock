# Implementation Plan: Media Attachments

**Branch**: `005-attachments` | **Date**: 2026-08-26 | **Spec**: [spec.md](./spec.md)

---

## Summary

Add WhatsApp Cloud API-compliant media attachment support to the mock service. Clients must be able to upload media files (image, audio, video, document, sticker), send media messages using an uploaded media ID or external URL, and retrieve/download media via the standard WhatsApp two-step pattern. Both backend API and frontend UI must be extended.

---

## Technical Context

**Language/Version**: TypeScript 5.7 (Node.js 22)

**Primary Dependencies**:
- Express 4.x (existing)
- Prisma 5.x with SQLite (existing)
- Multer 2.x (existing — currently audio only, extend to all media types)
- Socket.IO 4.x (existing — for real-time UI updates)
- `crypto` (Node built-in — for SHA-256 hashing)

**Storage**:
- SQLite (Prisma) — new `Media` model for metadata
- Local filesystem — `backend/uploads/media/<type>/` directories

**Testing**: Manual validation via `curl` + browser UI (see [quickstart.md](./quickstart.md))

**Target Platform**: Linux server (Docker Compose)

**Project Type**: Web service (REST API + React frontend)

**Performance Goals**: Media upload < 1 second for 5 MB file; standard Express static file serving for downloads.

**Constraints**:
- Must maintain 100% WhatsApp Cloud API payload parity
- No breaking changes to existing endpoints (text messages, audio, webhook logs, chats)
- Local filesystem storage only (no cloud storage)

**Scale/Scope**: Development/testing mock — not production scale
